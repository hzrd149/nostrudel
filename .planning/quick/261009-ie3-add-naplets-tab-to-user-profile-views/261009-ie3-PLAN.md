<objective>
Add a "Napplets" tab to user profile views. It shows how many napplets (NIP-5D apps, which the user calls "Naplets") the profile owner has published and lists them as cards. Each card has a one-click "Open" button that launches the napplet through the existing `/app/<naddr>` launch path.

Purpose: Today the only way to find a user's napplets is the global App Store or the "More by this author" strip on a napplet's detail page. With this tab, visiting a profile lets you see their published napplets and try one directly.

Output: The App Store card and listing predicate become shared modules, so the App Store and the new tab render the same card from the same code. Also a new `UserNappletsTab`, its registration in `userProfileTabs`, and a minor changeset.
</objective>

Supporting facts already established by the planner (do not re-derive):

- "Naplet" in the user's request means napplet, a NIP-5D app. The word "naplet" appears nowhere in `src/`. In UI text, use "Napplets"/"napplet" to match the rest of the app (`src/components/navigation/apps.ts`, the App Store, the `/napplets` routes).
- Napplet manifest kinds come from `@kehto/nip` and are re-exported by `src/helpers/nostr/napplets.ts`: `NAPPLET_KIND_SNAPSHOT` = 5129 (immutable release, no `d` tag), `NAPPLET_KIND_ROOT` = 15129 (replaceable), `NAPPLET_KIND_NAMED` = 35129 (addressable). The App Store Discover tab lists only ROOT and NAMED. The profile tab must do the same so the count is "napplets", not "releases".
- `src/services/event-store.ts` builds a default `new EventStore()` that collapses replaceable events. `useTimelineLoader` returns `TimelineModel` over that store, so each napplet coordinate appears once at its newest version and `timeline.length` is a correct count of distinct napplets. Do not route around the store (`useNappletVersions` does that on purpose for version history, but that is not wanted here).
- Launch path: the store detail page's "Open" button links to `/app/${naddr}`. `src/views/app/index.tsx` (`AppView`, route `app/:id` in `src/app.tsx`) parses the naddr and renders `NappletRouteLoader`, which loads the event and mounts `NappletFrame`. `NappletFrame` is an iframe with `sandbox="allow-scripts"`, and its capability requests go through the consent modal wired in `src/providers/global/napplet-shell-provider.tsx`. Linking to `/app/<naddr>` is the whole "try it out" path. Add no new launch logic.
- Card links: App Store cards link to `/app/store/<naddr>` (detail page with Open, Install, Zap). Keep that as the card's main click target and add the Open button next to it.
- `NappletStoreCard` (memo) and the `isValidNappletStoreEvent` predicate are private to `src/views/app/store.tsx` today. Grep confirms neither is used anywhere else. Shared napplet view components already live in `src/views/napplets/components/` (`installed-napplet-card.tsx`, which store.tsx imports as `../napplets/components/installed-napplet-card`).
- The App Store card is currently `Card as={RouterLink}`, so the whole card is one `<a>`. A nested Open link would be an invalid nested anchor, which also matters after the Phase 7 accessibility pass. Use the LinkBox pattern instead. Chakra 2.10.10's `LinkBox` gives every nested `a[href]` that is not the overlay `position: relative; z-index: 1` (node_modules/.pnpm/@chakra-ui+react@2.10.10*/.../link/link-box.mjs). So a `Button as={RouterLink}` inside the box stays clickable above the `LinkOverlay` without manual z-index. Use Chakra's plain `LinkOverlay`, not the repo's `HoverLinkOverlay` (`src/components/hover-link-overlay.tsx`). That one adds a tinted hover layer the store card never had, which would change the store's look.
- User profile tab conventions (see `src/views/user/tabs/polls.tsx`, `emoji-packs.tsx`, `torrents.tsx`): `useParamsProfilePointer("pubkey")`, relays from `useUserOutbox(user) || []`, `useTimelineLoader(\`${user.pubkey}-<name>\`, relays, { authors: [user.pubkey], kinds: [...] }, { eventFilter })`, `useTimelineCurserIntersectionCallback(loader)` (it also fires the initial `loader(-Infinity)` block on mount), `IntersectionObserverProvider`, `ScrollLayout`, `LoadMoreButton`. Follow the existing tab pattern and show the count of loaded napplets. One relay block is `limit: 100`, so in practice the count is complete, and `LoadMoreButton` covers the rest.
