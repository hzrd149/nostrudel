## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| page -> system clipboard / Web Share sheet | The new menu hands a string to `navigator.clipboard.writeText` and, via `ShareLinkMenuItem`, to the OS share sheet |
| napplet manifest event -> rendered menu | The event is relay-sourced and attacker-controllable in its tag content |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-r34-01 | Information disclosure | copy item in `napplet-menu.tsx` | low | accept | The only value copied is the NIP-19 naddr, which is derived from the event's own public kind/pubkey/`d` tag plus relay hints and is already public. Nothing account-scoped or secret reaches the clipboard. |
| T-r34-02 | Tampering | `getSharableEventAddress` relay hints | low | accept | The relay hints folded into the naddr come from the event's own tags, so a hostile publisher can point a shared address at relays it controls. This is pre-existing behaviour of every share surface in the app (`NoteMenu`, `StreamMenu`), unchanged by this plan, and the hints cannot alter which event the coordinate resolves to. |
| T-r34-03 | Spoofing | `ShareLinkMenuItem` title, built from the event's `title` tag | low | accept | Reused verbatim from the existing shared component; the title is rendered as text into a share sheet, never as markup. No new exposure - the same component already runs on the note and stream surfaces. |
| T-r34-04 | Denial of service | removal of the manifest-pointer display | low | accept | The naddr stops being visible on the page. Recovery path is the new copy item plus "View Raw", so the string is still reachable; this is the user's locked D-01/D-03 trade. |

No package-manager install is part of this change, so no package-legitimacy gate applies.
