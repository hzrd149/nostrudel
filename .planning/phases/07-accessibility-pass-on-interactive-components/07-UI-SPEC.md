# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Nature of this phase:** semantics-only. No new screens, no new visual design, no new tokens, no new
copy except accessible names. The contract is (1) **visual parity** after every `role` → native-element
conversion (D-13) and (2) the **interaction/semantics contract** the converted elements must satisfy.
Everything below is derived from `07-CONTEXT.md` (D-01..D-17) and from code read on `next` @ `98bf028c6`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable — Chakra UI project, no `components.json`; Registry safety gate: not applicable) |
| Preset | not applicable |
| Component library | Chakra UI `@chakra-ui/react` ^2.10.10 (React 19.2, `framer-motion` ^10) |
| Icon library | `@chakra-ui/icons` ^2.2.4 plus local `src/components/icons` |
| Font | Chakra default system font stack (no custom `fonts` in `src/theme/`); monospace only for `loading-nostr-link` details |
| Theme source | `src/theme/index.ts` (`buildTheme`, runtime `primary` palette from the user's `primaryColor`, default `#8DB600`), `src/theme/default/index.ts` (gray scale, semantic tokens, Card/Button/Drawer/Modal/Menu overrides) |
| CSS reset | Chakra `CSSReset` (via `ChakraProvider`, `src/providers/global/index.tsx`) — relevant facts below |

**Chakra CSS reset facts that drive the parity contract** (read from `@chakra-ui/react/dist/esm/css-reset/css-reset.mjs`):

- `button` already gets `background: transparent; padding: 0; margin: 0; font-family: inherit; font-size: 100%; line-height: 1.15; text-transform: none`, and `:where(button, [role="button"]) { cursor: pointer }`.
- `button` does **not** get `color: inherit`, `text-align: start`, `font-weight` inheritance, or `line-height: inherit` (reset line-height is 1.15, not the body's 1.5).
- `:where(ol, ul)` gets `margin: 0; padding: 0` but **no** `list-style: none`. Set `listStyleType="none"` explicitly on every `as="ul"` / `as="li"` conversion.
- `main { display: block }` is applied by the reset.
- Chakra v2's `Button` draws its focus ring with `_focusVisible: { boxShadow: "outline" }`. A bare `<button>` or `Flex as="button"` does not get that.

No new type styles. Converted elements must render with the **same** size, weight, and line-height as before.
Because a native `<button>` resets differently from a `div` (see reset facts), converted buttons carry
`font="inherit"` and `lineHeight="inherit"` (see Conversion Contract).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (inherited) | 16px (`md`) | 400 (normal) | 1.5 (Chakra body default) |
| Label / secondary (wallet balance `fontSize="sm"`) | 14px (`sm`) | 400 | 1.5 |
| Emphasis (`fontWeight="bold"`: wallet name, "Show More") | 16px | 700 (bold) | 1.5 |
| Heading (article `Heading size="xl"`, unchanged) | existing Chakra `xl` | existing | existing |

Weights touched by this phase: 400 and 700 only (both already in use). Nothing is added.

## Interaction Contract

### Keyboard and activation (converted buttons)

| Behavior | Requirement |
|----------|-------------|
| Reachability | Converted buttons are in the natural Tab order with **no `tabIndex`** attribute (native `button`). |
| Activation | Enter **and** Space fire `onClick` natively. No hand-written `onKeyDown` anywhere (D-07). |
| Type | Every converted button has `type="button"` (none are inside forms; this prevents accidental submit). |
| Focus visibility | Every converted button shows a visible focus indicator on keyboard focus only (`:focus-visible`), using `_focusVisible`. Default: `{ boxShadow: "outline" }` (matches Chakra `Button`). For `relay-icon-stack` (`overflow: hidden` clips outside rings) use an **inset** ring: `{ outline: "2px solid", outlineColor: "primary.500", outlineOffset: "-2px" }`. No ring on mouse click. |
| Pressed state | Toggle-style buttons expose `aria-pressed` (wallet select, relay filter toggles). Disclosure-style expose `aria-expanded` (already present on `loading-nostr-link` details toggle). |
| Non-interactive | "Show More" is not a focus stop and not announced as a button. |
| Nesting | No interactive element is nested inside another (wallet card rule above). |

### Landmark structure

- Exactly **one** `main` per page, rendered by `VerticalPageLayout`'s inner `Flex as="main"`. `article.tsx` must not add a second.
- At most one `nav` named `Main navigation` visible per layout (desktop `side-nav`, or mobile `nav-drawer` when open).
- Landmarks created by `as` (`nav`, `main`, `article`, `section`, `footer`) keep their existing `aria-label`s; a `section` is a `region` landmark **only because it has an accessible name**, so `aria-label` on `invoice-modal` and `loading-nostr-link` details is mandatory.
- `footer` nested inside `article` is intentionally **not** a page `contentinfo` landmark.

### Live regions

- **No page-wide `aria-live`** (D-04): `VerticalPageLayout` must not set `aria-live` or `aria-atomic`.
- `loading-nostr-link.tsx:72` `Heading aria-live="polite"` is a small, scoped status heading; leave as is (not a bucket-F finding, not touched by D-04).

### Composite widgets

- **Relay URL input (D-10):** native `<input type="url" list="relay-suggestions">` + `<datalist>`; the browser owns combobox/listbox semantics and the suggestion popup. Typing, picking a suggestion, Enter-to-normalize (`handleKeyDown`), and blur-normalize behave exactly as before. Status text in the `srOnly` element keeps announcing loading/error/count via `aria-describedby`.
- **Composer autocomplete (D-11):** `react-textarea-autocomplete` still owns its `ul.rta__list > li.rta__item`; items render the same visible content (avatar, name, NIP-05 icon / emoji + name). Mouse and keyboard selection (`@` mention, `:` emoji) behave exactly as before. No ARIA listbox is added (deferred idea).
- **Privacy share-service field (D-12):** `<input list="share-services">` shows the same four suggestions (`https://njump.me/`, `https://nostr.com/`, `https://nostr.at/`, `https://nostr.eu/`) rendered from one array; URLs stay inline here (move to `src/const.ts` is Phase 8).

### Iframes

- Both iframes expose a non-empty `title` per the accessible-name table; sandboxing and `allow` attributes untouched.

### Decorative image

- Identicon `<img alt="">` is skipped by screen readers; the surrounding avatar link/name remains the announced label. `width="100%"` and `borderRadius` untouched.
