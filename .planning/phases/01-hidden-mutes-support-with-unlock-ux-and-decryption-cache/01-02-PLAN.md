<objective>
Fix the write path so unmute is correct for both halves of the mute list, and make `isMuted` merged state. Today every unmute surface unconditionally takes the public-tag path, so unmuting a privately-muted pubkey publishes an unchanged list — the exact silent no-op D-13 forbids.

Purpose: D-13 requires that nothing removable in the UI silently does nothing; D-14 fixes it by detecting which half the pubkey lives in; D-15 makes `isMuted` read from merged state so a privately-muted user reads as muted once unlocked.

Output: a new `getMuteHalf` helper plus half-aware unmute in the shared hook and in the app-wide mute menu item.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → signer | The hidden unmute branch calls applesauce's `UnmuteUser(pubkey, true)`, which re-encrypts the hidden tag set through the signer — one signer round trip per hidden unmute. |
| app → relays | Every unmute publishes a replacement kind-10000 event to the user's relays. A malformed draft would overwrite the authoritative mute list. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | hidden unmute branch in `use-user-mute-actions.ts` | high | mitigate | A hidden-half write that starts from a locked list could destroy existing private entries. Mitigated by delegating entirely to applesauce's `UnmuteUser(pubkey, true)`, whose `modifyHiddenTags` unlocks the existing hidden tags before modifying them, so the republished ciphertext always contains the full prior set. This plan writes zero tag-manipulation or encryption code of its own. |
| T-01-05 | Repudiation | undeterminable-half unmute | medium | mitigate | Publishing an unchanged list would tell the user "unmuted" while nothing changed, leaving them believing a mute was lifted. Mitigated by the unknown branch throwing a descriptive Error (surfaced as a toast by `useAsyncAction`) plus the disabled menu item — never a fall-through to the public path (D-13). |
| T-01-06 | Information Disclosure | merged `isMuted` | low | accept | While the hidden half is locked, `isMuted` reports public-only and may say "not muted" for a privately-muted pubkey, which could lead a user to publish a public mute duplicating a private one. Accepted explicitly by D-15 and consistent with D-07; deduplication is a deferred idea. |
| T-01-SC | Tampering | npm/pnpm installs | high | mitigate | No new packages. `applesauce-actions`, `applesauce-common`, and `applesauce-core` are already direct dependencies at 6.2.0. No install command may appear in this plan's commits. |
</threat_model>
