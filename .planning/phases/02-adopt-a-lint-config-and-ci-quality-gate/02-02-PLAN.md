Add the CI quality gate workflow and document the adopted lint standard for contributors and coding agents.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request / branch push → GitHub Actions runner | Contributor-controlled code, including forks, is checked out and scanned by third-party tooling. |
| runner steps → GITHUB_TOKEN | The job token is available to every step unless it is scoped. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Elevation of Privilege | lint.yml job token | medium | mitigate | Workflow-level `permissions: contents: read`, `persist-credentials: false` on checkout, and no credentials referenced. Only the standard pull_request event is used, so fork PRs run with a read-only token (acceptance greps on lint.yml). |
| T-02-04 | Tampering | gate outcome | medium | mitigate | No soft-fail setting, and the run line is exactly `run: pnpm lint:ci` with nothing appended (anchored grep), so a failing gate cannot report success (D-03). |
| T-02-05 | Tampering | aislop binary used in CI | medium | mitigate | The workflow invokes only `pnpm lint:ci`, which resolves the exact-pinned lockfile version from plan 02-01. No package-runner download appears in the workflow (acceptance grep). |
| T-02-06 | Repudiation | inline ignore directives hiding findings | low | accept | D-12 makes enforcement review-based by decision. AGENTS.md requires rule names and a reason on every directive, so each suppression is attributable in diff review. |
</threat_model>
