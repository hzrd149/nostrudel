| .aislop/config.yml → every scan and CI run | The config decides what the gate can see. An over-broad exclude or ignore silently removes first-party code from enforcement. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-07 | Tampering | exclude list and file-level ignore | medium | mitigate | Exactly four vendored paths, each with an upstream-source comment (acceptance: 4 entries, 4 comments). No blanket src/lib exclude and no .aislopignore. The error-logger.ts ignore is scoped to one rule, and a scan shows other rules still fire on that file. |
| T-02-08 | Information Disclosure | `telemetry.enabled: true` (plain init default) | low | accept | D-05 locks the plain defaults. The repository is public open source, so scan metadata reveals nothing non-public. Turning telemetry off later is a one-line, explicit config change for the maintainer. |
| T-02-09 | Denial of Service | `security.audit: true` dependency audit inside scans | low | accept | Plain default per D-05, bounded by `auditTimeout: 25000`. Plan 02-05 calibration checks whether audit findings leak into changed-file gate results and stops for a maintainer decision if they do. |
