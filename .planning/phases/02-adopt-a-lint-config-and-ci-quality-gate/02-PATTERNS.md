## Pattern Assignments

### `.github/workflows/lint.yml` (CI workflow, request-response)

**Analogs:** `.github/workflows/nsite.yml` (setup steps) and `.github/workflows/docker-image.yml` (branch-trigger shape)

**Checkout + toolchain setup pattern** (`.github/workflows/nsite.yml` lines 15-27):
```yaml
steps:
  - name: Checkout Repo
    uses: actions/checkout@v4

  - uses: pnpm/action-setup@v4

  - name: Setup Node.js 24
    uses: actions/setup-node@v4
    with:
      node-version: 24
      cache: "pnpm"

  - name: Install Dependencies
    run: pnpm install
```
Copy this block verbatim into `lint.yml`, but override the checkout step with `fetch-depth: 0`
(D-13 requires full history so `--base origin/master` resolves — `nsite.yml` doesn't need this
since it never diffs against a ref).

**Branch-push trigger pattern** (`.github/workflows/docker-image.yml` lines 3-7):
```yaml
on:
  push:
    branches:
      - "**"
```
Adapt to D-13's `push: branches-ignore: [master]` + `pull_request:` (see RESEARCH.md's verified
`lint.yml` skeleton for the exact merged form — already vetted against this repo's conventions).

**Concurrency group pattern** (`.github/workflows/nsite.yml` lines 9-11, also in
`docker-image.yml` lines 9-11):
```yaml
concurrency:
  group: "nsite"
  cancel-in-progress: true
```
Not mandated by any decision, but matches existing workflow style — consider adding
`concurrency: { group: lint-${{ github.ref }}, cancel-in-progress: true }` for consistency
(planner's discretion; not a locked decision).

**Job/step naming style:** Existing workflows use `Title Case` step names (`"Checkout Repo"`,
`"Setup Node.js 24"`, `"Install Dependencies"`) — match this for the new `"Lint (changed files
only)"` step running `pnpm lint:ci`.

### `package.json` (config, scripts + devDependencies)

**Analog:** the file's own existing `scripts` block (lines 11-19)

**Existing pattern** (`package.json` lines 11-19):
```json
"scripts": {
  "start": "vite serve",
  "dev": "VITE_APP_VERSION=dev vite serve",
  "build": "tsc --project tsconfig.json && vite build",
  "build-icons": "node ./scripts/build-icons.mjs",
  "build-native-icons": "pnpm dlx @capacitor/assets generate --android --ios ...",
  "analyze": "pnpm dlx vite-bundle-visualizer -o ./stats.html",
  "format": "prettier --ignore-path .prettierignore -w .",
  "cap-sync-version": "pnpx capacitor-set-version@2 set . -v=$(jq -r .version package.json) -b=1"
}
```
Scripts are short one-liner shell invocations of a CLI tool, no wrapper scripts. Follow the same
style — insert alphabetically-adjacent to existing entries (or grouped near `format`, its closest
sibling concern):
```json
"lint": "aislop scan .",
"lint:ci": "aislop ci --changes --base origin/master"
```

**devDependencies:** no existing devDependency block was inspected in this pass, but D-14 requires
`"aislop": "0.16.1"` (bare version string, no `^`/`~`) — achieved via
`pnpm add -D aislop@0.16.1 --save-exact`, not by hand-editing (hand-editing risks the lockfile
falling out of sync; let pnpm do it, matching how every other dependency in this file was added
via package manager, not manual edits).

### `AGENTS.md` ("Linting" section, doc)

**Analog:** existing top-level `##`/`###` sections in the same file, e.g. the "Error Handling"
section structure (heading, short prose, fenced code block, bullet list of rules).

**Section style pattern** (structure observed via `grep -n "^##" AGENTS.md`): sections use `##`
for major topics (e.g. `## Common Patterns`, `## Adding New Views`) and `###` for subtopics under
"Code Style Guidelines". A new `## Linting` (or `### Linting` nested under "Code Style Guidelines")
section should:
- State `pnpm lint` (informational, `aislop scan .`) vs `pnpm lint:ci` (the real gate, mirrors CI)
  — matching the Anti-Pattern noted in RESEARCH.md so contributors don't treat `pnpm lint`'s exit
  code as meaningful.
- Document the D-12 inline-ignore convention: `aislop-ignore-line` / `-next-line` / `-file`
  directives must name the rule(s) and give a `-- reason`; bare directives are not acceptable.
- Note the `origin` vs `gh` remote-naming caveat (Pitfall 7) — instruct contributors to
  `git fetch origin master` before trusting a local `pnpm lint:ci` result.
