  <action>
Convert the three flagged handlers to `useAsyncAction`, following the call-site shape in
`napplet-menu.tsx`: destructure `{ loading, run }` and rename `run` to the handler's existing name
so the JSX call sites keep working.

For each converted handler, delete the hand-rolled `try`/`catch`/`finally` scaffolding and the
`console.error` plus failure `toast` in the catch — the hook already toasts the caught error's
message and logs it. Keep the success-path `toast` call inside the callback, because the hook only
auto-toasts on the failure path. List every closed-over value in the dependency array.

Handle the loading state deliberately. The clear-all and refresh handlers currently track loading
with module-local booleans that map cleanly onto the hook's own `loading` flag, so their
hand-rolled state goes away. The single-cache clear handler is different: its state is a cache
name, not a boolean, and the table renders a spinner on one row by comparing that name against the
row's cache name. The hook's `loading` is a single boolean with no concept of which invocation is
running, so replacing the name-valued state with it would collapse per-row feedback into
every-row feedback. Preserve the existing behaviour: keep a small name-valued state used solely to
decide which row shows its spinner, set it at the top of the `useAsyncAction` callback and clear
it at the end, and let the hook own the error and toast handling. Do not drop the per-row
distinction — that would be a silent behaviour reduction.

Leave the load handler at lines 44-61 completely untouched. It was not flagged, its catch has a
different shape because it also resets the cache list before toasting, and it is not named in
D-05 or D-07. Converting it would be scope creep.

Make no other change to this file.
  </action>
