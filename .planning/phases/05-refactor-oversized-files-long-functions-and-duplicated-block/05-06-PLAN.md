  <name>Task 2: Factor the shared notification timeline-loader composition (D-05)</name>

  <files>src/services/notifications/common.ts</files>

  <action>
All three loaders are built the same way: combine the active account with the inbox list, map over
the pair, return null when there is no account or no inbox, otherwise create a timeline loader over
the pool and those inboxes with a filter array and a shared options object carrying the same limit,
the same cache request function and the same event store, then replay the single created timeline.

They differ in exactly one thing: the filter array. The share loader filters on repost kinds, the
social loader on text-note, article and comment kinds plus a second filter for the user's own
timeline, and the zap loader on the zap kind.

Extract one internal factory that takes a function mapping the account's public key to a filter
array, and returns the composed observable. Define the three exported loaders by calling it with
their own filter builders.

Preserve three properties precisely:

- The three exported names and their observable element types must not change. The notifications
  view imports all three by name, and changing a type would ripple into it.
- Each loader must keep replaying its single created timeline to late subscribers. That replay is
  what stops a second subscriber creating a duplicate timeline, and dropping it would change
  runtime behaviour while looking like a pure refactor.
- Every filter's kinds and tag selectors must be carried across verbatim, including the social
  loader's second filter over the user's own authored notes and the comment that explains why it
  exists.

Leave the mailbox and inbox observables at the top of the file and the authored-event set at the
bottom untouched.
  </action>
