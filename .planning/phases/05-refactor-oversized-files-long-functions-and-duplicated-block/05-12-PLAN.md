  <action>
Create the two modal components under `src/components/napplets/`, beside the frame, the info
drawer and the menu. That directory is the established home for napplet UI, which is why D-09
chose it over the two alternatives it rejected: putting JSX under the services directory, which
cuts against the layer separation, and opening a third napplet UI location under the providers
directory.

Move the consent modal's markup into `consent-modal.tsx`. It renders the grant-access dialogue: the
app title in a code span, the sentence saying access lasts until the frame is closed, the list of
requested capabilities, and three buttons — deny, allow once, and always allow. Give it a default
export and an explicit prop type taking the pending consent request and a respond callback that
accepts the allow flag and the always flag.

Move the intent-choice modal's markup into `intent-choice-modal.tsx`. It renders the
choose-a-napplet dialogue: the sentence naming the archetype and action that no installed app
declares support for, the list of installed apps as buttons, and a cancel button. Give it a default
export and an explicit prop type taking the pending intent choice, the installed napplet list and a
respond callback that accepts an optional handler.

Pass everything through props. Neither modal may import the shell hook from the provider — the
provider imports and renders these components, so a hook import would close an import cycle between
them. Everything each modal needs is already in the provider's hands at the point it renders them.

Preserve the consent semantics exactly. Three distinct outcomes exist today and all three must
survive as distinct: deny revokes the recorded capability set, allow once grants for the session,
and always allow grants and additionally persists the identity to the always-allow list. Do not
merge the two allow buttons, do not change which one persists, and do not change the dismissal
behaviour — closing the dialogue is equivalent to denying, and that must remain true.

Preserve the intent-choice dismissal too: cancelling and closing both resolve with no handler.

Follow the directory's conventions: import grouping as in the frame component, default export,
explicit prop type, and relative imports with no path alias.

Land this as a move-only commit per D-16. The markup moves verbatim; what changes is that values
previously read from the enclosing scope arrive as props. Say so in the commit message, since that
makes it not strictly byte-identical.
