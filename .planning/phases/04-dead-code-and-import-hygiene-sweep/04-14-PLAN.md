<objective>
Close the round-2 UAT blocker on 04-UAT.md test 2: with PoW difficulty above 0, `MinePOW` now mounts
(04-12 and 04-13 fixed that), but under `pnpm dev` every miner worker throws
`ReferenceError: window is not defined` at `vite/dist/client/env.mjs:8` before `miner.ts` runs, so
the pool mines zero hashes and mining never completes.

The diagnosed root cause (`.planning/debug/pow-workers-fail-to-load.md`) is one value in
`vite.config.ts`. The `define` block (lines 41-44, added in 74ece28df) maps `global` to `window`.
In dev, Vite inlines that value verbatim into the `/@vite/env` prelude, and Vite prepends that
prelude to every module worker. Worker scopes have no `window`. The fix changes the value to
`globalThis`. On the main thread `globalThis` is the same object as `window`, so 74ece28df's fix is
unchanged there, and it also exists in workers and the service worker. This plan also aligns
`src/polyfill.ts` to `globalThis` and records the fix in the debug session.

Purpose: this is the last code defect between the user and a working PoW composer. It also blocks
runtime confirmation of three other things: UAT test 4 (blocked outright), the post-"Found POW" half
of test 3, and D-12's `cleanup()` on test 1, which can only be observed once a mine completes.
Closing it lets one UAT re-run confirm or refute everything 04-12, 04-13 and this plan changed.

Output: two one-line source edits (one per commit), a debug-session update (one docs commit), and a
SUMMARY that hands the runtime checks to the UAT re-run with exact steps.

**The defect, reproduced at plan time with Vite's own code.** `vite.config.ts` line 43 sets the
`global` define to the string `window`. Vite 8.1.5's `clientInjectionsPlugin` (name
`vite:client-inject`, in `node_modules/vite/dist/node/chunks/node.js` around line 24826) applies
only to non-bundled (dev) environments. It replaces `__DEFINES__` in `dist/client/env.mjs` line 8
using `serializeDefine`, whose `handleDefineValue` returns string values **raw**, unquoted. The
served line is therefore `const defines = {"global": window};`.

The `<verify>` command in Task 1 resolves the real config through `vite.resolveConfig`, takes the
real `vite:client-inject` plugin out of `config.plugins`, runs its `buildStart` and `transform` on
the real env.mjs, and evaluates the result in a `node:vm` context that has `self` and no `window`.

bundle has no free `global` and no env prelude, so prod workers were never affected and are not
changed now. Many other chunk filenames change hash. That is expected cascade from content-hash
imports and is not a signal.

**Why `globalThis` and not something else.** It is the value the diagnosis validated (Experiment A).
It is the only identifier that is the same object as `window` on the main thread and also exists in
dedicated workers and service workers. The build targets (`chrome89`, `edge89`, `firefox89`,
`safari15`) all support it. **Removing the define instead is not acceptable.** The SW bundle and the
Capacitor chunk would then ship a bare `global` reference, which is the regression 74ece28df fixed.

**The polyfill.** `src/polyfill.ts` is 4 lines: line 1 is `console.log("polyfill global");`, line 2
is blank, line 3 is `// @ts-ignore`, and line 4 is a logical-OR assignment that aliases `global` onto
the window object. `src/index.tsx:1` imports it, so it runs on the main thread only. There, a
`globalThis`-based form is identical in behaviour, so the change is consistency only. The diagnosis
listed it as optional, and this plan adopts it so that both shims for `global` name the same
realm-agnostic object. The project has **no `@types/node`** (`node_modules/@types` has no `node`
entry), so `global` is not a declared property of `typeof globalThis`. The `// @ts-ignore` is still
required, or `tsc` (the first half of `pnpm build`) fails.
