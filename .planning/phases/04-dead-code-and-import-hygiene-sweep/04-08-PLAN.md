**D-12 — `src/components/pow/mine-pow.tsx` line 47.** Read in full at plan time, and the
call-versus-delete question D-12 leaves open is now answered: make it a call.

Inside `miner()`, `stopMiner` is a *parameter* declared at line 24, and the caller passes
`stopMiner.current` — the cleanup belonging to the *previous* mining run. `cleanup` is a separate
local declared at line 61 that terminates the workers created by *this* run. So line 46's
`stopMiner()` and line 47's intended `cleanup()` tear down two different worker sets; calling
`cleanup()` is not redundant with the line above it.

It is also safely callable there. Line 47 sits inside `handleMessage`, which only ever runs as a
`worker.onmessage` callback wired at line 56 — asynchronously, after the synchronous setup that
declares `cleanup` at line 61 has finished. The binding is out of its temporal dead zone by then.

Line 47 currently carries a comment copy-pasted verbatim from line 46, describing the wrong
function. Correct it to describe terminating this run's workers.

`() => {}` returned from the branch taken when Web Workers are unavailable. It is a deliberate no-op
cleanup satisfying the `MinerCleanup` return contract, not an unfinished stub.

`src/components/content/links/image.tsx` line 67.** Both read as a negated guard short-circuiting

`wrapperStyle` both at line 65 — plus one pre-existing `react-hooks/rules-of-hooks` error. This plan
owns the parameters so 04-05 can exclude the file entirely. The hook-order error is backlog 999.2
