<measured_facts>
**Why a residue exists at all.** Measured at plan time, `eslint/no-unused-vars` reported 103 findings
whose message says a symbol is imported but never used, but only 64 of them share an exact
file-and-line with an `ai-slop/unused-import` finding — and only the latter rule drives the fixer.
Research measured the fixer taking `eslint/no-unused-vars` from 208 to 125, which leaves roughly 20
unused-import findings standing. Nine of those are certain: they sit in files with no
`ai-slop/unused-import` finding at all, so the fixer never visits them.

**The nine certain survivors** (line numbers from plan time; they will have shifted):
`src/components/content/components/nip.tsx:1` (`Link`),
`src/components/embed-event/card/embedded-dvm.tsx:3` (`AddressPointer`),
`src/services/notifications/zaps.ts:5` (`AddressPointer` and `EventPointer`, two findings),
`src/views/articles/components/article-tags.tsx:1` (`Tag`),
`src/views/feeds/relays/relay-feed.tsx:3` (`kinds`),
`src/views/settings/outbox-selection/components/relay-count-row.tsx:4` (`UserAvatar`),
`src/views/support/components/other-zap.tsx:1` (`Text`),
`src/views/thread/components/tabs/zaps.tsx:1` (`Text`).

**The rest of the set is not knowable at plan time** — it depends on what the fixer actually reached
and on which imports waves 2 and 3 orphaned. Derive it at execution with the scan rather than working
from a fixed list.

**The four duplicate imports that survive by design.** `ai-slop/duplicate-import` merges duplicates
within a contiguous import group but will not merge across the blank line separating external
library imports from internal ones. Research confirmed four files where the duplicate straddles that
boundary: `src/components/embed-event/card/embedded-zap-receipt.tsx`,
`src/components/layout/presets/app-tabs-layout.tsx`, `src/components/timeline/highlight.tsx` and
`src/views/badges/badge-details.tsx`.

`badge-details.tsx` was inspected directly: `@chakra-ui/react` appears once in the top external
block and again lower down for `useDisclosure`, and `nostr-tools` likewise for `kinds` versus
`NostrEvent`. The remedy is to lift the stragglers up into the existing top-block import.

**Three of these files carry inherited error-severity findings** — `embedded-zap-receipt.tsx` has 1,
`app-tabs-layout.tsx` has 2, and `use-user-bookmarks-list.ts` (if it appears in the derived set) has
4. They are `react-hooks/rules-of-hooks`, backlog 999.2, and must not be fixed here (D-15).

**CONVENTIONS.md § Import Organization governs the result:** external libraries first, then internal
shared modules by relative path, then feature-local imports. Merging must not move an import across
those groups other than to collapse a genuine duplicate into the earlier occurrence.
</measured_facts>

| Boundary | Description |
|----------|-------------|
| lint report → import deletion | A symbol used only in a type or JSX-namespace position can be misread as unused |
| merged import → module semantics | Collapsing a type-only import into a value import changes emit behaviour under `isolatedModules` |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04-28 | Tampering | losing type-only semantics when merging into a value import | medium | mitigate | Type-only specifiers must carry an inline `type` modifier across; `pnpm build` runs `tsc` with `isolatedModules` enabled, which surfaces the failure. |
