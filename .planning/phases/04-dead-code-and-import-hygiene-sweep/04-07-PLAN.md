<measured_facts>
**The directive format is fixed by AGENTS.md § Inline ignores:** `aislop-ignore-file`,
`aislop-ignore-line` or `aislop-ignore-next-line`, naming the rule, then ` -- ` and the reason. A
directive without a rule or without a reason is not acceptable. The two in-repo instances to copy
the shape from are `src/sw/client/error-logger.ts` line 1 (file-level) and
`src/hooks/timeline/use-timeline-cache-key.ts` line 14 (next-line).

**D-08 raises the bar above "this is deliberate":** the reason must justify why the code could not
be *fixed* instead. Phase 3's D-07 set this precedent.

**Site 1 — `src/services/sqlite/index.ts` lines 9-15 (D-09).** Read at plan time: line 7 opens
`if (CAP_IS_WEB) {`, line 8 throws to stop the web build loading this module, and lines 9-15 are the
jeep-sqlite dynamic import, custom-element registration and `initWebStore()` call that the throw
makes unreachable. The findings are `eslint/no-unreachable` on lines 9, 10, 12, 13, 14 and 15, plus
`ai-slop/unreachable-code` on line 9 — 7 findings over a 7-line contiguous block.

A `-next-line` directive covers exactly one line, so covering this block that way would mean
inserting six comment lines into a seven-line block, each insertion shifting the lines below it.
The file-level form naming both rules is the narrowest directive that actually works here, and this
file contains no other unreachable code for it to over-suppress. That over-suppression risk is
T-04-02 and is mitigated by the verification below.

**Site 1b — the same file, line 43, `const dbName` inside `deleteDatabase`.** This is a genuinely
dead local, explicitly carved out of D-09's exception and deleted under D-07. Its right-hand side is
a pure getter call, so deleting the whole statement is safe.

**Site 2 — `src/components/magic-textarea.tsx` line 25 (D-10).** A bare `[Textarea, Input];`
expression that exists only to keep both imports referenced, already carrying a comment saying so.
It must be ignored rather than removed: deleting it would leave both imports unused and 04-01's
auto-fixer would then strip them.

**Site 2b — the same file, line 78, an unused `data` parameter.** This plan owns it so that 04-05
can exclude this file entirely and the two plans never contend for it.

**Sites 3 and 4 — `src/components/post-modal/index.tsx` line 102 and
`src/views/new/note/short-text-form.tsx` line 98 (D-11).** Both are a bare `formState.isDirty;`
property read. This is react-hook-form's getter-subscription idiom — the read is what registers the
subscription, so deleting it silently breaks form reactivity with no type error.

Line numbers shift after 04-01 — locate each site by its code, not its line.
</measured_facts>
