<objective>
Make the IndexedDB wrapper genuinely typed (D-05) and collapse the migration chain's 16 casts into
one reasoned helper (D-06), in a single green commit.

Purpose: `SchemaV1`..`SchemaV13` are plain interfaces that are not assignable to idb's `DBSchema`,
so in idb 8.0.3 `StoreNames<SchemaV13>` falls through to `string` and `StoreValue` to `any`: the
current schema typing checks nothing (it accepts `"totally-not-a-store"`). Rewriting the schemas as
type aliases makes them assignable to `DBSchema`, which turns on real store-name and value checking
for every consumer. The migration chain needs to view the upgrade database at past schema
versions, which the type system cannot track; one helper holds that single, reasoned cast.

This runs last (D-16) because it is the riskiest change: it executes on the startup path
(top-level-await `openDB`). D-07 (plan 06-04) already removed the one consumer line real typing
would reject; D-08 already removed the v5 directive.

Output: 16 bucket-E findings cleared; one rule-scoped ignore added; zero consumer edits expected.
</objective>

- `function atSchema<Schema extends DBSchema>(db: IDBPDatabase<SchemaV13>, transaction: UpgradeTransaction<SchemaV13>): { db: IDBPDatabase<Schema>; transaction: UpgradeTransaction<Schema> }` (module-private), plus a local `at<Schema>()` shorthand inside `upgrade()`.

The phase-wide artifact inventory is in `06-01-PLAN.md`.

Note on D-05's wording: CONTEXT says the schemas "extend DBSchema". In TypeScript that is realized
as "are assignable to DBSchema" (type aliases). Do not look for, or add, a literal
`interface ... extends DBSchema` in `schema.ts`; RESEARCH Pitfall 1 shows that form drops stores.
