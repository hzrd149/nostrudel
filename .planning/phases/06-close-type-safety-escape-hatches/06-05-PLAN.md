<objective>
Replace the six napplet-shell and WebLN library-boundary casts with real types (D-11): an explicit
pool adapter and filter conversion in the napplet adapter, cast-free reaction drafting, and the
existing global `Window.webln` augmentation in the WebLN backend.

Purpose: each cast hides a mismatch that is ours, not the library's. The pool cast also hides a
real but dormant hazard: applesauce's `RelayPool.count()` returns an Observable while kehto's
optional `RelayPoolLike.count` expects a number, so a future kehto that probes `count` would get the
wrong thing. An explicit adapter that exposes only what kehto calls removes that trap.

Output: 6 bucket-E findings cleared in four files.
</objective>

- `@kehto/shell` `RelayPoolLike`: `subscription(relayUrls: string[], filters: any)` returning an
  object with `subscribe(observer)`; `publish(relayUrls: string[], event: any): void | Promise<void>`;
  `request(relayUrls: string[], filters: any)`; optional `count?(relayUrls, filters: NostrFilter[]):
  number | Promise<number>`.
- `@kehto/shell` dist `createRelayPoolAdapter` calls only `pool.subscription(urls, filters)` and
  `return pool.publish(relayUrls, event)`; `@kehto/runtime` consumes that publish result only as
  `Promise.resolve(publishResult).then(() => settle(true), (error) => settle(false, message))`.
  Nothing in `@kehto/{shell,runtime,services}` calls `count` on the pool.
- applesauce-relay `RelayPool.publish(relays, event)` resolves to `PublishResponse[]`;
  `RelayPool.count(...)` returns an Observable of per-relay count responses.
- `@napplet/core` exports `NostrFilter` (an interface without nostr-tools `Filter`'s tag index
  signature, which is why a spread copy is assignable but the interface itself is not).
- applesauce-common `ReactionFactory.create(event, emoji: string | Emoji)` resolves to a
  `ReactionTemplate`, which is already an `EventTemplate`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| napplet iframe -> kehto shell -> relay pool | Sandboxed napplets supply filters and publish requests that the shell forwards to the app's relay pool |
| browser extension -> `window.webln` | A WebLN provider injected by an extension (or any page script) is trusted to make invoices and send payments |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-13 | Elevation of Privilege | `poolLike` handed to kehto | medium | mitigate | The explicit adapter exposes only `subscription`, `request` and `publish`; previously the whole applesauce `RelayPool` object reached the shell. Acceptance asserts no `count` member and exactly one adapter object |
| T-06-14 | Tampering | napplet filters -> `pool.subscription` | medium | mitigate | `toRelayFilters` is a shallow copy with no validation change (D-15), so exactly the same filters reach the pool as before; relay-tier selection is untouched |
| T-06-15 | Repudiation | napplet publish result | low | mitigate | The async `publish` resolves when `pool.publish` resolves and rejects when it rejects; kehto's runtime reports ok/failed from settle only, so napplets receive the same result |
| T-06-16 | Spoofing | `window.webln` provider | low | accept | Trust in the injected provider is unchanged; this plan only changes how its type is expressed |
</threat_model>
