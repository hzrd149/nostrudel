  <action>
    Use the Edit tool on `AGENTS.md` — never Write, which would destroy the other 470-plus lines.

    Insert one new `####` subsection titled "Swallowed Exceptions" immediately after the
    `#### Error Patterns` bullet list (which ends at line 130) and before `### State Management`
    (line 132). Keep the file's existing register: terse bullets, backticked identifiers, a short
    fenced example only where it earns its place.

    The subsection must state all five rules this phase established, because each one is a mistake a
    future contributor would otherwise repeat:

    1. **A reason comment alone is not enough.** `ai-slop/swallowed-exception` is error-severity and
       gates `pnpm lint:ci` on any touched file. Its detector looks for control flow or a logging call
       in the catch body, not for comment presence. State this explicitly — it is the single most
       surprising fact in the whole convention, and `src/components/relay-url-input.tsx` was a live
       example of a well-commented catch that still failed the gate.
    2. **A deliberate parse or filter guard takes a reason comment plus an explicit exit** —
       `return` in a function body, `continue` in a loop, or returning the accumulator in a `reduce`
       callback. Name the shape and note that the exit must reproduce whatever value the code already
       fell through to, so behavior does not change.
    3. **When code after the catch must still run, log the cause instead of returning.** A
       `log(...)` call inside the catch also satisfies the rule, and it is the correct form for a
       best-effort fallback where the fallback itself is the handling — a pending-map cleanup, an
       effect-cleanup registration, a fallback render, or the next iteration of a retry loop. The user
       sees no change; the cause becomes recoverable. Point at `src/services/event-cache/index.ts` as
       the in-repo example.
    4. **A failure in a user-triggered action belongs to `useAsyncAction`.** Delete the local
       try/catch and let the error throw; the hook toasts `e.message` and logs it, and its `loading`
       replaces any hand-rolled loading state. Cross-reference the existing
       "useAsyncAction Hook (REQUIRED)" section rather than restating the hook's API.
    5. **Logging goes through the namespaced debug logger**, `logger.extend("<Module>")` from
       `src/helpers/debug.ts` — silent in production unless the namespace is enabled. State that the
       direct browser-console channel is not used for this, because `ai-slop/console-leftover` is on.
    6. **A rule-scoped ignore is the last resort**, allowed only where the catch genuinely cannot
       return a value or log, and its `-- reason` must justify why the code could not be fixed instead
       — not merely that the behavior is deliberate. Cross-reference the existing `#### Inline ignores`
       subsection for the directive syntax rather than duplicating it, and note that a
       `-line`/`-next-line` directive must sit textually adjacent to the flagged line.

    Do not restate the `pnpm lint` / `pnpm lint:ci` mechanics — the `### Linting` section already
    covers them; reference it instead. Do not edit any other part of `AGENTS.md`.
  </action>
