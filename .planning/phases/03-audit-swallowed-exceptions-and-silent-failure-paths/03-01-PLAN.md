## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | `logger.extend("EncryptedStorage")` log call in `unlock()` | low | mitigate | Log the caught Error only — never the password, the derived key, or decrypted plaintext. `logger` is the `debug` package, silent in production unless the namespace is explicitly enabled, so nothing is emitted by default. |
| T-03-02 | Tampering | `encrypted-storage.tsx` conflates wrong-PIN with corrupt ciphertext | medium | accept | Pre-existing and unchanged by this plan. The root cause is AES-CBC without authentication plus a 10,000-iteration PBKDF2, recorded in `.planning/codebase/CONCERNS.md` and explicitly deferred by CONTEXT.md as a separate security item. This plan only makes the discarded error observable; distinguishing the two cases requires an authenticated cipher mode and is out of scope. Not on a primary remote trust boundary (local storage only), so ASVS L1 permits acceptance with rationale. |
| T-03-03 | Information Disclosure | `logger.extend("BlobRepair")` log calls | low | accept | Logs a blob URL, a server URL and an Error. All three are already user-visible in the repair UI; the namespaced logger is off by default in production. |
| T-03-04 | Denial of Service | Blob repair fallback loop | low | accept | Loop bounds, break condition and terminal throw are unchanged by this plan; only logging is added. |

No new attack surface is introduced: this plan adds no network call, no new input parser, no new
stored data and no new exported API. Package installs: none, so no supply-chain threat applies.
